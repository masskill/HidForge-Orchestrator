# HidForge Orchestrator

[English](README.md) · [Українська](README.uk.md) · **Русский**

Локальный оркестратор AI-агентов для программирования, сделанный в первую очередь для Windows. Работает с **Claude Code, Codex CLI, Antigravity (`agy`), Cursor Agent CLI** и JSON-плагинами (Gemini CLI, OpenCode).

Вы описываете цель. HidForge разбивает её на граф задач (DAG) и параллельно запускает нескольких агентов, каждого в собственном изолированном git worktree. Каждый результат проходит независимые проверки и ждёт вашего **Approve & Merge**. В итоге у вас один целостный репозиторий, а состояние переживает перезапуск.

Всё работает на вашем компьютере. HidForge использует уже установленные CLI, в которые вы вошли. Он не запрашивает, не хранит и никуда не передаёт API-ключи, токены или куки.

> **Статус: v0.5 (бета).** Общий прогресс — 96% ([ROADMAP](docs/ROADMAP.md)). Что и как проверено: [TEST_REPORT](docs/TEST_REPORT.md).

## Возможности

| Направление | Что есть |
|---|---|
| **Планирование** | LLM-планировщик (только чтение): цель → проверенный DAG задач → черновики, которые вы просматриваете. Ручные задачи с зависимостями, ролями, разрешёнными путями и командами проверки |
| **Выполнение** | Параллельные агенты в отдельных git worktree; DAG-планировщик с приоритетами, повторами с задержкой, таймаутами и обнаружением зависаний; один писатель на workspace; восстановление после перезапуска |
| **Качество** | Gate-ы: разрешённые пути, маркеры конфликтов, команды проверки (каждая требует вашего разрешения один раз). AI-ревьюер (QA + Security) — рекомендательный или обязательный. Repair-цикл с замечаниями. Задача Integrator, если проверка после merge падает |
| **Управление** | Живые логи, diff, Approve & Merge / Reject с пояснением, остановка / повтор, бюджет проекта и лимит стоимости задачи |
| **Обзор** | Страницы: Проекты, Обзор, Задачи (таблица / kanban / граф), Планировщик, Агенты, Журнал событий, Расходы, Отчёты и решения (ADR), Система, Настройки |
| **Продукт** | Установщик (без прав администратора), запуск без терминала, обновление только fast-forward, диагностика, автоматические ежедневные резервные копии |
| **Опционально** | Бэкенды WSL2 и VPS через SSH (экспериментально, по умолчанию выключены) |

Интерфейс: тёмная мятная дизайн-система, чистый JS без сборки ([DESIGN_SYSTEM](docs/DESIGN_SYSTEM.md)).

## Поддержка агентов

| Агент | Состояние |
|---|---|
| Claude Code | ✅ реальные задачи, планировщик и ревьюер проверены от начала до конца |
| Antigravity `agy` | ✅ реальные задачи, планировщик и ревьюер, без обхода разрешений |
| Cursor Agent CLI | ✅ проверено, когда вы разрешите доверие к worktree HidForge в Настройках (без `--force` / `--yolo`) |
| Codex CLI | 🟡 сессии только для чтения работают. Запись файлов на проверенном ПК блокирует Windows-песочница Codex (см. [Решение проблем](#решение-проблем)). HidForge берёт самый новый `codex.exe` из десктопного приложения Codex, иначе `codex` из PATH |
| Gemini CLI, OpenCode (JSON-плагины) | 🟡 установлены и обнаружены; реальные задачи не проверены (вход отложен) |
| Mock Agent | ✅ встроенный: демо-режим и тесты, без вызовов AI и без расходов |

Агент, который не установлен или в который не выполнен вход, показывается как недоступный — с причиной. Остальное приложение продолжает работать.

## Требования
- Windows 10/11 x64. На Linux и macOS должно работать, но не проверялось.
- **Node.js 24 или новее** (встроенный `node:sqlite` и запуск TypeScript без сборки).
- **Git 2.x** с поддержкой `worktree` (проверено на 2.54).
- Необязательно: один или несколько CLI агентов, установленные под вашей учётной записью и с выполненным входом (`claude`, `codex`, `agy`, `cursor-agent`). Без них можно пользоваться Mock Agent.

Не нужны: Docker, tmux, WSL2, сервер, домен, платные API.

## Установка

1. Установите [Node.js 24+](https://nodejs.org/) и [Git for Windows](https://git-scm.com/download/win).
2. Скачайте код:
   ```powershell
   git clone https://github.com/masskill/HidForge-Orchestrator.git
   ```
   ```powershell
   cd HidForge-Orchestrator; npm install
   ```
3. Создайте ярлыки. Установщик только проверяет Node.js и Git и создаёт **HidForge Orchestrator** на рабочем столе и в меню «Пуск». Больше ничего не устанавливает, права администратора не нужны:
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\install.ps1
   ```
4. Один раз войдите в нужные CLI агентов их собственным способом: запустите в терминале `claude`, `codex`, `agy` или `cursor-agent` и пройдите вход. HidForge использует этот вход.

Удалить ярлыки (данные останутся): `powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -Uninstall`.

## Первый запуск
- Дважды щёлкните **HidForge Orchestrator**. Сервер стартует без окна терминала, а UI открывается в браузере по адресу `http://127.0.0.1:4317`. Повторный запуск просто открывает уже запущенный экземпляр.
- Или из терминала: `npm run dev`. С демо-проектом и Mock-агентами (без расхода квоты): `npm run demo`.
- Остановить сервер: **Налаштування → Про програму → Зупинити сервер** (Настройки → О программе → Остановить сервер).
- Журнал сервера: `%LOCALAPPDATA%\HidForge\hidforge.log`. Данные (база, worktree, резервные копии): `%LOCALAPPDATA%\HidForge`.

## Как пользоваться
Интерфейс на украинском; ниже названия кнопок даны в оригинале и в переводе.

1. **Откройте проект.** На странице «Проєкти» (Проекты) укажите путь к Git-репозиторию и нажмите «Відкрити» (Открыть) или создайте демо-проект. Во время merge репозиторий должен быть на ветке без незакоммиченных изменений.
2. **Проверьте агентов.** Страница «Агенти» (Агенты) показывает установленные CLI, версии, состояние входа и причину недоступности.
3. **Спланируйте.** На странице «Планер» (Планировщик) напишите цель, выберите агента (или `mock`) и нажмите «Згенерувати план» (Сгенерировать план). Агент работает только на чтение и предлагает DAG задач. Просмотрите его и нажмите «Додати як чернетки» (Добавить как черновики) или «Відхилити» (Отклонить).
   Или создайте задачи вручную кнопкой **+ Задача**: название, инструкции, критерии приёмки, роль, агент (`auto` выбирает по политике cost-first / balanced / quality-first), права (`read-only` / `workspace-write`), зависимости `#id`, разрешённые пути (glob), команды проверки.
4. **Запустите.** Нажмите «Запустити план» (Запустить план). Независимые задачи стартуют параллельно (по умолчанию по 2). Зависимые ждут, пока их зависимости будут слиты.
5. **Следите.** Откройте задачу: живой журнал, evidence и diff. Если gate впервые хочет выполнить команду проверки, появятся «Дозволити / Заборонити» (Разрешить / Запретить).
6. **AI-ревью (по желанию).** В **Налаштування → AI-рецензент** (Настройки → AI-ревьюер) выберите `off` (по умолчанию), `advisory` (только информирует) или `required` (merge только после вердикта `approve`; `request_changes` возвращает задачу агенту с замечаниями). Ревьюер работает только на чтение в отдельном временном worktree.
7. **Решите.** Нажмите **Approve & Merge** или **Reject** с пояснением — агент получит его в следующей repair-попытке. Конфликт merge ничего не ломает: задача становится `blocked`, а «Повторити» (Повторить) сливает базовую ветку в ветку задачи и просит агента разрешить конфликт.
8. **Посмотрите итоги.** Страницы «Огляд» (Обзор), «Витрати» (Расходы) и «Звіти» (Отчёты) показывают итоги, расходы и markdown-отчёт с журналом решений (ADR).

## Настройки
В интерфейсе (**Налаштування** — Настройки): тема, число параллельных агентов, политика автовыбора, бюджет проекта, AI-ревьюер, шаблоны ролей (инструкции, только чтение, разрешённые агенты), доверие Cursor к worktree, опциональные агенты WSL / SSH.

Параметры запуска — в файле `.env` (скопируйте [.env.example](.env.example)). Секретов в нём нет:

| Переменная | По умолчанию | Значение |
|---|---|---|
| `HIDFORGE_DATA_DIR` | `%LOCALAPPDATA%\HidForge` | база, worktree, резервные копии |
| `HIDFORGE_PORT` | `4317` | порт UI/API, всегда на `127.0.0.1` |
| `HIDFORGE_MAX_CONCURRENT` | `2` | параллельные агенты (можно менять и в UI) |
| `HIDFORGE_STALL_TIMEOUT_SEC` | `600` | остановить агента, который столько времени ничего не выводит |

**Расходы.** HidForge перестаёт запускать новые задачи, когда заявленные расходы достигают бюджета проекта. Лимит задачи передаётся Claude Code как `--max-budget-usd`. Суммы в USD сообщает Claude Code; токены считаются для всех агентов, которые их сообщают.

## Обновление, диагностика, резервные копии
Проверить наличие обновления, затем обновиться. Только fast-forward из `origin`; при локальных изменениях HidForge откажется обновляться:
```powershell
powershell -ExecutionPolicy Bypass -File scripts\update.ps1 -Check
```
```powershell
powershell -ExecutionPolicy Bypass -File scripts\update.ps1
```
Диагностика: Node, Git, папка данных и свободное место, целостность базы, версия схемы, резервные копии, репозитории проектов, агенты. Безопасно и при запущенном сервере:
```powershell
node scripts\doctor.ts
```
То же есть в **Налаштування → Діагностика й резервні копії** (Настройки → Диагностика и резервные копии). Согласованная копия состояния (`VACUUM INTO`) делается при запуске не чаще раза в сутки в `%LOCALAPPDATA%\HidForge\backups`; хранятся 10 последних. Восстановление: остановите сервер, удалите `hidforge.db-wal` и `hidforge.db-shm` и скопируйте нужную копию вместо `hidforge.db`.

## Безопасность
- Никогда не использует `--dangerously-skip-permissions`, `--yolo`, `danger-full-access` и похожие флаги. Интерактивное доверие к workspace не обходится. Доверие для Cursor включаете только вы.
- Процессы запускаются без shell. Команды проверки выполняются только после вашего разрешения. Жёсткий deny-list (git push/reset, rm/del, powershell/cmd/bash, curl/wget, npm publish, deploy, shell-операторы …) нельзя разрешить никогда — в том числе в форме с кавычками, полным путём или глобальными опциями git.
- Токены, ключи и куки провайдеров не хранятся. Секреты в логах маскируются.
- API слушает только `127.0.0.1`, проверяет заголовок `Host` и требует токен для изменений. В UI строгая CSP.
- Агенты пишут только в свой worktree. Изменения вне разрешённых путей не проходят gate. Без вашего Approve & Merge ничего не попадает в вашу ветку.

Модель угроз и подробности: [docs/SECURITY.md](docs/SECURITY.md) (на украинском).

## Решение проблем

| Проблема | Что сделать |
|---|---|
| Агент «не установлен» | Проверьте, что CLI запускается в терминале (`claude --version` и т. п.). Затем нажмите «Перевірити знову» (Проверить снова) на странице «Агенти» |
| Агент «без входа» | Запустите CLI в терминале и один раз войдите. HidForge никогда не запрашивает пароли или ключи |
| Codex: `sandbox initialization error`, файлы не записываются | Папка песочницы Codex `%USERPROFILE%\.codex\.sandbox-bin` принадлежит администраторам. Сменить владельца или права — ваше решение (это настройка безопасности). Проверка без расхода квоты: `codex sandbox -- cmd /c echo ok` |
| Cursor не запускает задачу | Включите доверие Cursor к worktree HidForge в Настройках |
| Merge отклонён: «uncommitted changes» | Закоммитьте или спрячьте (stash) изменения в репозитории проекта и повторите merge |
| UI не открывается | Запустите `node scripts\doctor.ts`, затем посмотрите `%LOCALAPPDATA%\HidForge\hidforge.log` |
| Порт 4317 занят | Укажите `HIDFORGE_PORT` в `.env` |

## Частые вопросы
**Нужны ли сервер, VPS или домен?** Нет. HidForge работает на вашем ПК и открывается только на `127.0.0.1`. VPS — опциональный бэкенд для запуска агентов на другой машине (чтобы разгрузить ПК, для Linux-среды или изоляции); по умолчанию он выключен.

**Используются ли платные API?** Сам HidForge их не вызывает. Агенты работают через ваши собственные подписки CLI. Mock Agent ничего не стоит.

**Отправляется ли мой код куда-либо?** Только выбранному вами провайдеру агента, через его собственный CLI.

**Можно ли добавить другого агента?** Да, JSON-плагином в `%LOCALAPPDATA%\HidForge\plugins` (примеры — в `plugins/`). Плагины, пытающиеся обойти разрешения, отклоняются.

## Для разработчиков
```powershell
npm run typecheck; npm run lint; npm test; npm run build
```
Собранная версия: `npm start`. Смоук-тесты на настоящих CLI тратят немного квоты вашей подписки (одна крошечная задача на агента):
```powershell
node scripts\smoke-real.ts claude agy
```
```powershell
node scripts\smoke-planner.ts claude:haiku agy
```
```powershell
node scripts\smoke-review.ts claude:haiku agy
```
Прогресс по этапам: `node scripts\progress.ts`.

Структура проекта:
```
src/            ядро (TypeScript, Node 24 запускает напрямую)
  orchestrator.ts  планировщик, запуски, gate-ы, merge, восстановление
  planner.ts       LLM-планировщик: цель → проверенный DAG → черновики задач
  reviewer.ts      AI-ревьюер (QA + Security)
  oneshot.ts       общая одноразовая read-only сессия агента
  report.ts        отчёт по проекту и журнал решений ADR
  maintenance.ts   диагностика и резервные копии
  store.ts, db.ts  SQLite: единственный источник истины, миграции, state machine
  workspace.ts     git worktree, diff, разрешённые пути, merge
  adapters/        Mock, Claude, Codex, Cursor, agy, JSON-плагины, WSL, SSH
  proc.ts          spawn без shell, завершение дерева процессов, маскировка секретов
  server.ts        REST + SSE + статика
web/            UI: styles/tokens.css, styles/ui.css, ui.js (компоненты), app.js (страницы)
plugins/        спецификации JSON-плагинов (Gemini CLI, OpenCode)
test/           unit- и e2e-тесты (настоящие процессы, git, SQLite)
scripts/        установщик, запуск, обновление, doctor, смоук-тесты, прогресс
```
