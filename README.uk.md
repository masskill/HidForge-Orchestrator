# HidForge Orchestrator

[English](README.md) · **Українська** · [Русский](README.ru.md)

Локальний оркестратор AI-агентів для програмування, зроблений насамперед для Windows. Працює з **Claude Code, Codex CLI, Antigravity (`agy`), Cursor Agent CLI** і JSON-плагінами (Gemini CLI, OpenCode).

Ви описуєте ціль. HidForge розбиває її на граф задач (DAG) і паралельно запускає кількох агентів, кожного у власному ізольованому git worktree. Кожен результат проходить незалежні перевірки й чекає на ваш **Approve & Merge**. У підсумку маєте один цілісний репозиторій, а стан переживає перезапуск.

Усе працює на вашому комп'ютері. HidForge використовує вже встановлені CLI, у які ви увійшли. Він не просить, не зберігає й нікуди не передає API-ключі, токени чи куки.

> **Статус: v0.5 (бета).** Загальний прогрес — 96% ([ROADMAP](docs/ROADMAP.md)). Що й як перевірено: [TEST_REPORT](docs/TEST_REPORT.md).

## Можливості

| Напрям | Що є |
|---|---|
| **Планування** | LLM-планер (лише читання): ціль → валідований DAG задач → чернетки, які ви переглядаєте. Ручні задачі із залежностями, ролями, дозволеними шляхами й командами перевірки |
| **Виконання** | Паралельні агенти в окремих git worktree; DAG-планувальник із пріоритетами, повторами з затримкою, таймаутами й виявленням зависань; один записувач на workspace; відновлення після перезапуску |
| **Якість** | Gate-и: дозволені шляхи, маркери конфліктів, команди перевірки (кожна потребує вашого дозволу один раз). AI-рецензент (QA + Security) — дорадчий або обов'язковий. Repair-цикл із зауваженнями. Задача Integrator, якщо перевірка після merge падає |
| **Керування** | Живі логи, diff, Approve & Merge / Reject з поясненням, зупинка / повтор, бюджет проєкту й ліміт вартості задачі |
| **Огляд** | Сторінки: Проєкти, Огляд, Задачі (таблиця / kanban / граф), Планер, Агенти, Журнал подій, Витрати, Звіти й рішення (ADR), Система, Налаштування |
| **Продукт** | Інсталятор (без прав адміністратора), запуск без термінала, оновлення лише fast-forward, діагностика, автоматичні щоденні резервні копії |
| **Опційно** | Бекенди WSL2 і VPS через SSH (експериментально, типово вимкнені) |

Інтерфейс: темна м'ятна дизайн-система, чистий JS без збірки ([DESIGN_SYSTEM](docs/DESIGN_SYSTEM.md)).

## Підтримка агентів

| Агент | Стан |
|---|---|
| Claude Code | ✅ реальні задачі, планер і рецензент перевірені наскрізно |
| Antigravity `agy` | ✅ реальні задачі, планер і рецензент, без обходу дозволів |
| Cursor Agent CLI | ✅ перевірено, коли ви дозволите довіру до worktree HidForge у Налаштуваннях (без `--force` / `--yolo`) |
| Codex CLI | 🟡 сесії лише для читання працюють. Запис файлів на перевіреному ПК блокує Windows-пісочниця Codex (див. [Розв'язання проблем](#розвязання-проблем)). HidForge бере найновіший `codex.exe` з десктопного застосунку Codex, інакше `codex` з PATH |
| Gemini CLI, OpenCode (JSON-плагіни) | 🟡 встановлено й виявлено; реальні задачі не перевірені (вхід відкладено) |
| Mock Agent | ✅ вбудований: демо-режим і тести, без викликів AI й без витрат |

Агент, який не встановлено або в який не виконано вхід, показується як недоступний — із причиною. Решта застосунку працює далі.

## Вимоги
- Windows 10/11 x64. На Linux і macOS має працювати, але не перевірялося.
- **Node.js 24 або новіший** (вбудований `node:sqlite` і запуск TypeScript без збірки).
- **Git 2.x** з підтримкою `worktree` (перевірено на 2.54).
- Необов'язково: один чи кілька CLI агентів, встановлені під вашим обліковим записом і з виконаним входом (`claude`, `codex`, `agy`, `cursor-agent`). Без них можна користуватися Mock Agent.

Не потрібні: Docker, tmux, WSL2, сервер, домен, платні API.

## Встановлення

1. Встановіть [Node.js 24+](https://nodejs.org/) і [Git for Windows](https://git-scm.com/download/win).
2. Завантажте код:
   ```powershell
   git clone https://github.com/masskill/HidForge-Orchestrator.git
   ```
   ```powershell
   cd HidForge-Orchestrator; npm install
   ```
3. Створіть ярлики. Інсталятор лише перевіряє Node.js і Git та створює **HidForge Orchestrator** на робочому столі й у меню «Пуск». Більше нічого не встановлює, права адміністратора не потрібні:
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\install.ps1
   ```
4. Один раз увійдіть у потрібні CLI агентів їхнім власним способом: запустіть у терміналі `claude`, `codex`, `agy` або `cursor-agent` і пройдіть вхід. HidForge використовує цей вхід.

Видалити ярлики (дані залишаться): `powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -Uninstall`.

## Перший запуск
- Двічі клацніть **HidForge Orchestrator**. Сервер стартує без вікна термінала, а UI відкривається в браузері за адресою `http://127.0.0.1:4317`. Повторний запуск просто відкриває вже запущений екземпляр.
- Або з термінала: `npm run dev`. З демо-проєктом і Mock-агентами (без витрати квоти): `npm run demo`.
- Зупинити сервер: **Налаштування → Про програму → Зупинити сервер**.
- Журнал сервера: `%LOCALAPPDATA%\HidForge\hidforge.log`. Дані (база, worktree, резервні копії): `%LOCALAPPDATA%\HidForge`.

## Як користуватися
1. **Відкрийте проєкт.** На сторінці «Проєкти» вкажіть шлях до Git-репозиторію й натисніть «Відкрити» або створіть демо-проєкт. Під час merge репозиторій має бути на гілці без незакомічених змін.
2. **Перевірте агентів.** Сторінка «Агенти» показує встановлені CLI, версії, стан входу й причину недоступності.
3. **Сплануйте.** На сторінці «Планер» напишіть ціль, оберіть агента (або `mock`) і натисніть «Згенерувати план». Агент працює лише на читання й пропонує DAG задач. Перегляньте його й натисніть «Додати як чернетки» (або «Відхилити»).
   Або створіть задачі вручну кнопкою **+ Задача**: назва, інструкції, критерії прийняття, роль, агент (`auto` обирає за політикою cost-first / balanced / quality-first), права (`read-only` / `workspace-write`), залежності `#id`, дозволені шляхи (glob), команди перевірки.
4. **Запустіть.** Натисніть «Запустити план». Незалежні задачі стартують паралельно (типово по 2). Залежні чекають, доки їхні залежності буде злито.
5. **Стежте.** Відкрийте задачу: живий журнал, evidence і diff. Якщо gate уперше хоче виконати команду перевірки, з'являться «Дозволити / Заборонити».
6. **AI-рецензія (за бажанням).** У **Налаштування → AI-рецензент** оберіть `off` (типово), `advisory` (лише інформує) або `required` (merge лише після вердикту `approve`; `request_changes` повертає задачу агенту з зауваженнями). Рецензент працює лише на читання в окремому тимчасовому worktree.
7. **Вирішіть.** Натисніть **Approve & Merge** або **Reject** з поясненням — агент отримає його в наступній repair-спробі. Конфлікт merge нічого не руйнує: задача стає `blocked`, а «Повторити» зливає базову гілку в гілку задачі й просить агента розв'язати конфлікт.
8. **Перегляньте підсумки.** Сторінки «Огляд», «Витрати» і «Звіти» показують підсумок, витрати й markdown-звіт із журналом рішень (ADR).

## Налаштування
В інтерфейсі (**Налаштування**): тема, кількість паралельних агентів, політика автовибору, бюджет проєкту, AI-рецензент, шаблони ролей (інструкції, лише читання, дозволені агенти), довіра Cursor до worktree, опційні агенти WSL / SSH.

Параметри запуску — у файлі `.env` (скопіюйте [.env.example](.env.example)). Секретів у ньому немає:

| Змінна | Типово | Значення |
|---|---|---|
| `HIDFORGE_DATA_DIR` | `%LOCALAPPDATA%\HidForge` | база, worktree, резервні копії |
| `HIDFORGE_PORT` | `4317` | порт UI/API, завжди на `127.0.0.1` |
| `HIDFORGE_MAX_CONCURRENT` | `2` | паралельні агенти (можна змінити й в UI) |
| `HIDFORGE_STALL_TIMEOUT_SEC` | `600` | зупинити агента, який стільки часу нічого не виводить |

**Витрати.** HidForge перестає запускати нові задачі, коли звітовані витрати досягають бюджету проєкту. Ліміт задачі передається Claude Code як `--max-budget-usd`. Суми в USD звітує Claude Code; токени рахуються для всіх агентів, які їх повідомляють.

## Оновлення, діагностика, резервні копії
Перевірити наявність оновлення, потім оновитися. Лише fast-forward з `origin`; за наявності локальних змін HidForge відмовиться оновлюватися:
```powershell
powershell -ExecutionPolicy Bypass -File scripts\update.ps1 -Check
```
```powershell
powershell -ExecutionPolicy Bypass -File scripts\update.ps1
```
Діагностика: Node, Git, тека даних і вільне місце, цілісність бази, версія схеми, резервні копії, репозиторії проєктів, агенти. Безпечно й при запущеному сервері:
```powershell
node scripts\doctor.ts
```
Те саме є в **Налаштування → Діагностика й резервні копії**. Узгоджена копія стану (`VACUUM INTO`) робиться при запуску не частіше разу на добу в `%LOCALAPPDATA%\HidForge\backups`; зберігаються 10 останніх. Відновлення: зупиніть сервер, видаліть `hidforge.db-wal` і `hidforge.db-shm` і скопіюйте потрібну копію замість `hidforge.db`.

## Безпека
- Ніколи не використовує `--dangerously-skip-permissions`, `--yolo`, `danger-full-access` чи схожі прапорці. Інтерактивна довіра до workspace не обходиться. Довіру для Cursor вмикаєте лише ви.
- Процеси запускаються без shell. Команди перевірки виконуються лише після вашого дозволу. Жорсткий deny-list (git push/reset, rm/del, powershell/cmd/bash, curl/wget, npm publish, deploy, shell-оператори …) не можна дозволити ніколи — зокрема й у формі з лапками, повним шляхом чи глобальними опціями git.
- Токени, ключі й куки провайдерів не зберігаються. Секрети в логах маскуються.
- API слухає лише `127.0.0.1`, перевіряє заголовок `Host` і вимагає токен для змін. В UI сувора CSP.
- Агенти пишуть лише у свій worktree. Зміни поза дозволеними шляхами не проходять gate. Без вашого Approve & Merge нічого не потрапляє у вашу гілку.

Модель загроз і деталі: [docs/SECURITY.md](docs/SECURITY.md).

## Розв'язання проблем

| Проблема | Що зробити |
|---|---|
| Агент «не встановлено» | Перевірте, що CLI запускається в терміналі (`claude --version` тощо). Потім натисніть «Перевірити знову» на сторінці «Агенти» |
| Агент «без входу» | Запустіть CLI у терміналі й один раз увійдіть. HidForge ніколи не просить паролів чи ключів |
| Codex: `sandbox initialization error`, файли не записуються | Тека пісочниці Codex `%USERPROFILE%\.codex\.sandbox-bin` належить адміністраторам. Змінити власника чи права — ваше рішення (це налаштування безпеки). Перевірка без витрати квоти: `codex sandbox -- cmd /c echo ok` |
| Cursor не запускає задачу | Увімкніть довіру Cursor до worktree HidForge у Налаштуваннях |
| Merge відхилено: «uncommitted changes» | Закомітьте або сховайте (stash) зміни в репозиторії проєкту й повторіть merge |
| UI не відкривається | Запустіть `node scripts\doctor.ts`, потім перегляньте `%LOCALAPPDATA%\HidForge\hidforge.log` |
| Порт 4317 зайнятий | Вкажіть `HIDFORGE_PORT` у `.env` |

## Часті питання
**Чи потрібні сервер, VPS або домен?** Ні. HidForge працює на вашому ПК і відкривається лише на `127.0.0.1`. VPS — опційний бекенд для запуску агентів на іншій машині (щоб розвантажити ПК, для Linux-середовища чи ізоляції); типово він вимкнений.

**Чи використовуються платні API?** Сам HidForge їх не викликає. Агенти працюють через ваші власні підписки CLI. Mock Agent нічого не коштує.

**Чи надсилається мій код кудись?** Лише обраному вами провайдеру агента, через його власний CLI.

**Чи можна додати іншого агента?** Так, JSON-плагіном у `%LOCALAPPDATA%\HidForge\plugins` (приклади — у `plugins/`). Плагіни, що намагаються обійти дозволи, відхиляються.

## Для розробників
```powershell
npm run typecheck; npm run lint; npm test; npm run build
```
Зібрана версія: `npm start`. Смоук-тести на справжніх CLI витрачають трохи квоти вашої підписки (одна крихітна задача на агента):
```powershell
node scripts\smoke-real.ts claude agy
```
```powershell
node scripts\smoke-planner.ts claude:haiku agy
```
```powershell
node scripts\smoke-review.ts claude:haiku agy
```
Прогрес по етапах: `node scripts\progress.ts`.

Структура проєкту:
```
src/            ядро (TypeScript, Node 24 запускає напряму)
  orchestrator.ts  планувальник, запуски, gate-и, merge, відновлення
  planner.ts       LLM-планер: ціль → валідований DAG → чернетки задач
  reviewer.ts      AI-рецензент (QA + Security)
  oneshot.ts       спільна одноразова read-only сесія агента
  report.ts        звіт по проєкту й журнал рішень ADR
  maintenance.ts   діагностика й резервні копії
  store.ts, db.ts  SQLite: єдине джерело істини, міграції, state machine
  workspace.ts     git worktree, diff, дозволені шляхи, merge
  adapters/        Mock, Claude, Codex, Cursor, agy, JSON-плагіни, WSL, SSH
  proc.ts          spawn без shell, завершення дерева процесів, маскування секретів
  server.ts        REST + SSE + статика
web/            UI: styles/tokens.css, styles/ui.css, ui.js (компоненти), app.js (сторінки)
plugins/        специфікації JSON-плагінів (Gemini CLI, OpenCode)
test/           unit- та e2e-тести (справжні процеси, git, SQLite)
scripts/        інсталятор, запуск, оновлення, doctor, смоук-тести, прогрес
```
