Ти — senior frontend engineer. Працюємо над HidForge Orchestrator: локальним веб-UI для оркестрації AI-агентів програмування. До повідомлення прикріплено:
- `HidForge_Style_Master_Prompt.md` — стиль; він обов'язковий;
- `docs/DESIGN_SYSTEM.md` — токени й компоненти;
- `web/ui.js`, `web/styles/*.css`, `web/app.js` — поточний код.

## Стек і жорсткі правила
- Тільки vanilla JS (ES-модулі) і CSS. Без збірки, без React, Tailwind і нових залежностей. Не міняй стек, навіть якщо майстер-промпт пропонує інший: він сам каже «follow the existing stack».
- Сторінки збирай тільки з компонентів `web/ui.js`: `PageHeader`, `PanelCard`, `StatCard`, `InfoList`, `Table`, `Tabs`, `Segmented`, `ItemCard`, `EmptyState`, `Badge`, `Button`-варіанти, `Field`, `TextInput`, `Select`, `Toggle`, `openModal`, `confirmModal`, `toast` тощо.
- Якщо потрібен новий візуальний елемент, додай його компонентом у `ui.js` і стилями в `ui.css`, лише на CSS-змінних з `tokens.css`. Жодних сирих кольорів.
- **Безпека:** ніякого `innerHTML`, `insertAdjacentHTML`, `outerHTML`. Весь текст виводь через `h()` / `textContent`. Markdown показуй як текст у `<pre>`, не рендери в HTML.
- **Мова:** усі тексти UI українською. Ідентифікатори коду — англійською.
- **Хелпери з `app.js`:** використовуй наявні `api()`, `act()`, `mount()`, `go()`, `toast()`, `usd()`, `reloadProject()`, `loadSettings()`, `loadAgents()`, `render()`, `renderShell()`, `ModelInput()`, `modelValue()`, а також `state`.
- **Маршрутизація:** hash-роутер `#/<page>`. Сторінки описані в масиві `PAGES`, а `render()` викликає `<page>Page()`. Сторінки, яким потрібен проєкт, перелічені в `needsProject` усередині `render()`.
- **Адаптивність:** на 375 px не має бути горизонтальної прокрутки сторінки. Таблиці вже стають картками, сітки йдуть в одну колонку.
- Нічого з наявної функціональності не можна втратити. Кожна кнопка, поле й виклик API, що були в «Налаштуваннях», мають лишитися доступними — просто на іншій сторінці.

## Задача
Сторінка «Налаштування» (`settingsPage()` у `app.js`) перевантажена. Розділи на ній зараз такі:
- Виконання
- Вигляд
- Бюджет (`budgetSettings`)
- AI-рецензент (`reviewSettings`)
- Довіра Cursor (`trustSettings`)
- Ролі (`rolesSettings`)
- Плагіни й WSL (`agentsExtSettings`)
- Діагностика й копії (`maintenanceSettings`)
- Про програму (`aboutSettings`)
- Дозволені команди

Розділи треба розкласти за змістом. Додай три сторінки в `PAGES` у такому порядку навігації:
1. Огляд
2. Задачі
3. AI-планер
4. Агенти
5. **Витрати** (`costs`)
6. **Звіти й рішення** (`reports`)
7. **Система** (`system`)
8. Налаштування

Для нових пунктів підбери іконки з наявних у `ui.js` або додай нові stroke-іконки 24×24 в `ICONS`.

### 1. «Витрати» — `#/costs` (потрібен проєкт)
- **Дані:** `GET /api/projects/:id/costs` (уже лежить у `state.costs` після `reloadProject()`). Формат:
  ```
  { totalUsd: number, budgetUsd: number|null, remainingUsd: number|null,
    byKind: { task: number, planner: number, review: number },   // USD за видом сесій
    byProvider: [{ provider, sessions, usd, sessionsWithUsd, inputTokens, outputTokens }] }
  ```
- **Верх сторінки:** `PageHeader`, далі ряд `StatCard`:
  - Витрачено;
  - Бюджет («не задано», якщо null);
  - Лишилось (tone `danger`, коли 0);
  - Сесій усього.
- **Розподіл за видом:** задачі / планер / рецензії, у USD. Можна як `StatCard`, можна як `InfoList`.
- **Таблиця за агентами:** перенеси сюди вміст `costsPanel()`. На «Огляді» таблицю прибери, а `StatCard` «Витрати» зроби посиланням на `#/costs`.
- **Форма бюджету:** перенеси сюди з `budgetSettings` з тією самою логікою `PATCH /api/projects/:id { budgetUsd }`.
- **Примітка:** долари звітує лише Claude Code, інші CLI — тільки токени.
- **Порожній стан:** коли сесій ще не було, показуй `EmptyState`.

### 2. «Звіти й рішення» — `#/reports` (потрібен проєкт)
- **Дані:**
  - `GET /api/projects/:id/report` повертає `{ markdown }`;
  - `GET /api/projects/:id/adr` повертає `{ markdown, decisions: [{ ts, title, context, decision, consequences, taskId? }] }`.
- **Вкладки** (`Tabs`): «Звіт» і «Рішення (ADR · N)».
- **«Звіт»:**
  - markdown у `<pre class="diff" style="white-space:pre-wrap">`;
  - кнопки «Копіювати» (`navigator.clipboard`) і «Завантажити .md» (Blob + `a.download`). Логіку візьми з `reportButton()`.
- **«Рішення»:**
  - кожне рішення — окрема картка: заголовок, дата, блоки «Контекст / Рішення / Наслідки»;
  - якщо є `taskId`, додай посилання `#/tasks/<id>`;
  - кнопка «Завантажити ADR .md»;
  - `EmptyState`, коли рішень немає.
- **Кнопка «Оновити»** у `PageHeader`.
- **Огляд:** кнопка «Звіт і рішення» має вести на `#/reports` (`go('#/reports')`). Модальне вікно `reportButton()` видали.

### 3. «Система» — `#/system` (проєкт НЕ потрібен)
- Перенеси сюди «Діагностика й резервні копії» (`maintenanceSettings`) і «Про програму» (`aboutSettings`) з тією самою логікою.
- Діагностику **не** запускай автоматично при відкритті сторінки, бо вона запускає процеси. Запуск — тільки кнопкою, як зараз.
- **Зверху** — короткий підсумок останньої діагностики, якщо її вже запускали в цій сесії: скільки OK / увага / помилок, як `Badge`. Збережи результат у `state.diag`.

### 4. «Агенти» — доповнити
Унизу сторінки `agentsPage()` додай розділи «Плагіни агентів і WSL2» (`agentsExtSettings`) і «Довіра до робочих каталогів» (`trustSettings`), бо вони стосуються агентів.

### 5. «Налаштування» — що лишається
Виконання, Вигляд, AI-рецензент, Ролі, Дозволені команди. Додай угорі рядок-підказку з посиланнями: «Витрати й бюджет → Витрати; діагностика, копії, версія → Система».

## Формат відповіді
Цілий `app.js` не повертай: він великий, а відповідь може обрізатися. Поверни **блоки змін**, кожен окремим code block, із заголовком однієї з форм:
- `REPLACE function <name>` — повна нова версія функції;
- `ADD after function <name>` — нова функція або константа повністю;
- `DELETE function <name>`;
- `REPLACE const PAGES` / `REPLACE in render(): <рядок needsProject>` — для точкових змін;
- `ui.js: ADD …` / `ui.css: ADD …` — якщо додаєш компонент або стилі.

У кінці додай:
1. стислий розбір кожної сторінки (мета, дії, блоки);
2. список використаних і нових компонентів;
3. ручний чек-лист перевірки: що клікнути, щоб переконатися, що нічого не загубилось.
