## Стек і жорсткі правила
- **Стек:** тільки vanilla JS (ES-модулі) і CSS. Без збірки, React, Tailwind і нових залежностей.
- **Компоненти:** сторінки збирай з компонентів `web/ui.js`: `PageHeader`, `PanelCard`, `StatCard`, `StatLink`, `InfoList`, `Table`, `Tabs`, `Segmented`, `ItemCard`, `EventCard`, `EmptyState`, `Badge`, `StatusBadge`, `Chip`, кнопки `Button`, `Field`, `TextInput`, `Textarea`, `Select`, `SearchInput`, `Toggle`, `openModal`, `confirmModal`, `promptModal`, `toast`.
- **Новий візуальний елемент** оформлюй компонентом у `ui.js` зі стилями в `ui.css`, лише на CSS-змінних з `tokens.css`. Сирих кольорів не має бути.
- **Безпека:** ніякого `innerHTML`, `insertAdjacentHTML` чи `outerHTML`. Текст виводь тільки через `h()` / `textContent`.
- **`null` серед дітей:** `replaceChildren(...)` друкує `null` як текст. Завжди обгортай дітей у `...clean(...)` з `app.js`.
- **Мова:** усі тексти UI українською. Ідентифікатори коду англійською.
- **Хелпери з `app.js`:** `api()`, `act()`, `mount()`, `clean()`, `go()`, `toast()`, `usd()`, `loadSettings()`, `loadAgents()`, `reloadProject()`, `render()`, `renderShell()`, `projectMeta()`, `STATUS_LABEL`, `state`.
- **Маршрутизація:**
  - hash-роутер `#/<page>`;
  - сторінки описані в масиві `PAGES`, а `render()` викликає `<page>Page()`;
  - сторінки, яким потрібен проєкт, перелічені в `needsProject`.
- **Живі оновлення:** SSE (`connectStream()`) після кожної не-output події через 150 мс робить `reloadProject()`, а потім `render()`. Для `projects` і `activity` перемальовується лише їхній вміст. Нова сторінка не повинна блимати «завантаженням» і не повинна губити введений текст. Тримай кеш у `state` і за потреби додай свою гілку в `connectStream()`, як для `activity`.
- **Адаптивність:** на ширині 375 px сторінка не має горизонтальної прокрутки.
- **Нічого не зламати:** усі наявні сторінки мають працювати як раніше.
- **Бекенд не змінюється.** Використовуй лише API, описане нижче. Якщо без нового ендпоінта не обійтися, не вигадуй його: опиши потребу в кінці відповіді.

## Задача
Додай дві сторінки. Порядок навігації в `PAGES`:
1. Проєкти, Огляд, Задачі;
2. **Запуски** (`runs`) — після Задач;
3. AI-планер, Агенти;
4. **Ролі** (`roles`) — після Агентів;
5. Журнал подій, Витрати, Звіти й рішення, Система, Налаштування.

Іконки підбери з `ICONS` або додай нові stroke-іконки 24×24.

### 1. «Запуски» — `#/runs` (потрібен проєкт)
- **Мета:** усі запуски агентів по задачах проєкту в одному місці. Тут видно, хто, скільки часу, з яким результатом і за скільки.
- **Дані:** `GET /api/projects/:id/runs?limit=100&before=<runId>&status=<s>&provider=<p>` повертає запуски від новіших до старіших:
  ```
  [{ id, taskId, taskTitle, attempt, provider, isMock, status, exitCode, error,
     startedAt, endedAt, durationMs, usd, inputTokens, outputTokens }]
  ```
  - `status`: `running | succeeded | failed | timeout | canceled | interrupted`;
  - `usd` дорівнює `null`, коли CLI не звітує доларів (так роблять усі, крім Claude Code);
  - `before` — для підвантаження старіших: найменший `id` із завантажених.
- **Ряд `StatCard`:** запусків (завантажених), успішних, з помилками (`failed`, `timeout`, `interrupted`), сумарний час, витрачено USD.
- **Фільтри** (у `state`):
  - `Select` статусу з українськими назвами: виконується / успішно / помилка / таймаут / скасовано / перервано;
  - `Select` агента зі списку `state.agents`;
  - фільтри працюють через query-параметри API (`status`, `provider`). Зміна фільтра перезавантажує першу сторінку.
- **Таблиця** (`Table`, на мобільному — картки):
  - `#id`;
  - задача: посилання `#/tasks/<taskId>` з назвою;
  - спроба;
  - агент з бейджем `MOCK`, якщо `isMock`;
  - статус (`Badge` з тоном);
  - початок (локальний час);
  - тривалість (`1 хв 05 с`; для `running` — «виконується»);
  - токени (вхід / вихід);
  - USD (`usd()` або «—»);
  - помилка: обрізана до ~120 символів, повний текст у `title`.
- **Підвантаження:** кнопка «Завантажити старіші», коли прийшло рівно `limit` записів.
- **Живі оновлення:** при подіях `run.started` і `task.status` перезавантаж першу сторінку, з дебаунсом. Кеш показуй одразу. Для `run.output` нічого не роби.
- **Порожній стан:** `EmptyState` з кнопкою «До задач».

### 2. «Ролі» — `#/roles` (проєкт НЕ потрібен)
- **Мета:** шаблони ролей (інструкції в контракті задачі й дозволи) на окремій сторінці, а не таблицею в «Налаштуваннях».
- **Дані:** `GET /api/settings` (уже лежить у `state.settings`, `loadSettings()`). Потрібні поля:
  ```
  roles: string[]                                   // 7 ролей у фіксованому порядку
  roleTemplates: { [role]: { instructions, readOnly, providers: string[] } }   // чинні (типові + ваші зміни)
  roleDefaults:  { [role]: { instructions, readOnly, providers } }             // типові
  ```
- **Збереження:** `PUT /api/settings { roleTemplates: { [role]: {...} } }`. Сервер **замінює** весь набір, тому надсилай усі ролі, крім скинутих. Роль, якої немає в наборі, повертається до типової. Невідомий агент у `providers` дає 400 з текстом помилки, його показуй у `toast`.
- **Сторінка:**
  - **картки ролей** (`ItemCard` або `PanelCard`), по одній на роль, у сітці: дві колонки на десктопі, одна на мобільному;
  - **у картці:** назва; бейдж «змінено», якщо чинний шаблон відрізняється від типового; `Textarea` інструкцій (до 4000 символів, з лічильником); `Toggle` «Лише читання»;
  - **«Дозволені агенти»:** набір `Chip`-перемикачів з `state.agents` (id + назва). Нічого не вибрано — дозволено будь-якого агента, і це видно підписом;
  - **кнопки в картці:** «Скинути до типової» (`confirmModal`, потім збереження без цієї ролі) і «Зберегти» для одної ролі (усі інші — як є);
  - **у `PageHeader`:** «Зберегти все» і «Скасувати зміни» (повернути поля до `state.settings`);
  - **незбережені зміни:** роль зі змінами позначається бейджем «не збережено». Чернетки тримай у `state`, щоб re-render від SSE їх не стер;
  - **пояснення вгорі:**
    - інструкції ролі додаються в контракт задачі для агента;
    - «Лише читання» примусово ставить задачі цієї ролі в режим read-only;
    - «Дозволені агенти» обмежують автовибір і ручний вибір у планувальнику.
- **«Налаштування»:** таблицю ролей (`rolesSettings()`) звідти прибери. Залиш посилання «Шаблони ролей → Ролі» в рядку-підказці вгорі, де вже є посилання на Витрати й Систему.
