## Етап 2 — реальні CLI
- ✅ Claude Code: реальний прогін задачі й планера
- 🟡 Codex CLI: HidForge бере найновіший `codex.exe` десктопного застосунку Codex (0.169, той самий вхід) — модель з вашого `config.toml` працює без явного вибору, read-only сесії ✅; запис файлів блокує пісочниця Codex: її тека `~/.codex/.sandbox-bin` належить «Администраторы», `SetNamedSecurityInfoW` → 5 (доступ заборонено). Права безпеки змінюєте ви; обходити sandbox не можна
- ✅ Antigravity `agy`: реальний прогін задачі й планера без bypass
- ✅ Cursor Agent CLI: запуск без PowerShell, список моделей; з вашим явним дозволом довіри до worktree HidForge реальний headless-прогін задачі пройшов (файл, gate, usage), без `--force`/`--yolo`
- ✅ Capability-based degradation: недоступний CLI не зупиняє проєкт
- ✅ Ліміти вартості: бюджет проєкту (зупиняє нові запуски) і ліміт задачі (`claude --max-budget-usd`); списки моделей з CLI (`agy models`, `cursor-agent models`, аліаси Claude) у підказках UI

- ✅ Дизайн HidForge Orange: помаранчеві дії й активні стани, м'ятні статуси успіху, нові токени темної й світлої теми
- ✅ 10 стилів вигляду × темна / світла + «Як у системі» (HidForge Themes v1.0): Налаштування → Зовнішній вигляд з живим переглядом, збереження й міграція старого вибору, без «спалаху»; контраст усіх 20 палітр перевірено (≥ 4.5:1)

## Етап 4 — інтелектуальна координація
- ✅ LLM-планер: ціль → валідований DAG → чернетки
- ✅ Автовибір агента за доступністю та політикою (cost-first / balanced / quality-first)
- ✅ Reviewer / repair loop: gate-и + repair-спроби; AI-рецензент QA + Security (advisory / required, repair із findings, API, UI), реальний прогін на Claude Code та agy
- ✅ Інтеграційний агент: repair конфлікту в тій самій задачі; провал інтеграційної перевірки після merge створює окрему чернетку Integrator (вивід перевірки, ті самі команди як критерій) — запуск лише користувачем
- ✅ Облік витрат: usage кожного запуску, планера й рецензії; зведення по проєкту й агентах (USD від Claude Code, токени від усіх)
- ✅ Зрозумілі звіти по проєкту: markdown-звіт (підсумок, задачі, проблеми, витрати, рішення) — перегляд, копіювання, завантаження в UI, `GET /api/projects/:id/report`
- ✅ Чат з ШІ в проєкті (`#/chat`): пряма розмова з агентом; кожна відповідь — окремий read-only запуск у тимчасовій копії репозиторію, історія в SQLite, одна відповідь за раз, «Зупинити», «Очистити»; агент — `auto` (planning/low) або вибраний вручну; панель чату на сторінці проєкту (Огляд); асистент бачить етапи, стан задач і помилки запусків; план із чату перевіряється як у планера й стає чернетками задач лише за кнопкою
- ✅ Автопілот: автоприйняття після схваленої AI-рецензії; автовиправлення заблокованих задач (діагноз ШІ → виправлена задача й повтор або просте питання власнику, до 2 разів); агент замість очікування погодження ставить питання власнику, відповідь — з інтерфейсу; пояснення блокування простими словами; «Пауза» / «Зупинити все» для проєкту й «Пауза» для задачі; перевірено на mock-агенті
- ⬜ Автовиправлення на справжній заблокованій задачі (діагноз реальним AI)
- ✅ Пам'ять рішень: evidence, історія, відновлюваний план; автоматичний журнал рішень ADR (прийняті плани, merge з перевірками й AI-рецензією, відхилення, Integrator) — `GET /api/projects/:id/adr`

## Етап 5 — продукт
- ✅ Інсталятор Windows: `scripts\install.ps1` для поточного користувача (перевірка Node/Git, ярлики на робочому столі й у «Пуск», `-Uninstall`); MSI/EXE не збирається
- ✅ Запуск без термінала: `scripts\HidForge.vbs` (прихований сервер + браузер, `--open`), повторний запуск відкриває вже запущений екземпляр, зупинка з UI
- ✅ Оновлення: `scripts\update.ps1` (`-Check`; лише fast-forward, відмова за наявності локальних змін), версія й коміт у «Про програму» (`GET /api/version`)
- ✅ Діагностика: `node scripts\doctor.ts` і панель у налаштуваннях (`GET /api/diagnostics`): Node, Git, тека даних і вільне місце, `quick_check`, версія схеми, резервні копії, репозиторії проєктів, агенти
- ✅ Резервне копіювання локального стану: `VACUUM INTO` (узгоджена копія без зупинки), авто при запуску раз на добу, 10 останніх, кнопка в UI; відновлення — вручну за інструкцією
- 🟡 Опційний WSL2 backend: обгортка `wsl.exe -d <дистрибутив> --cd /mnt/... --exec <CLI>` (без shell), агенти `<id>-wsl` з налаштувань, діагностика; на цьому комп'ютері WSL не ввімкнено, тож на реальному дистрибутиві не перевірено
- 🟡 Плагінні адаптери (JSON): завантажувач і валідація ✅ (промпт лише через stdin, прапорці обходу дозволів відхиляються, лише ім'я команди з PATH), специфікація Gemini CLI за офіційною документацією ✅; Gemini CLI 0.68.0 встановлено, але вхід через Google для особистих акаунтів Google закрив (17.11.2026: `IneligibleTierError … migrate to Antigravity`) — працює лише з платним `GEMINI_API_KEY`, на реальному ключі не перевірено
- Поза планом (рішення 17.11.2026): VPS/ssh-бекенд — HidForge працює лише на ПК; OpenCode — працює через платний шлюз, не потрібен. Код адаптерів лишається в репозиторії, але не розвивається й не рахується в прогресі

## Етап 6 — автомаршрутизація
- ✅ Тип, складність і зусилля задачі: планер позначає `category`/`complexity`, поля у формі задачі; зусилля передається в Claude Code (`--effort`) і Codex (`-c model_reasoning_effort=`)
- ✅ Таблиця пріоритетів 10 типів × 3 складності (`src/routing.ts`, `docs/ROUTING.md`): головний → заміна 1 → заміна 2, жодної ланки вище `high`
- ✅ Ескалація: невдала спроба йде до наступної ланки (інша модель/вендор, не більше зусиль); запуск зберігає агента, модель і зусилля
- ✅ Рецензент іншого вендора, ніж автор коду
- ✅ Налаштування: стеля зусиль, Fable як остання ланка (типово вимкнено), «агент не може записувати файли», редагована таблиця
- ✅ Власна статистика за (тип, складність, агент, модель, зусилля) і сторінка «Аналітика моделей»
- 🟡 Самонавчання (порядок ланок за вимірами, ≥ 5 запусків на ланку): реалізовано й покрито тестом; на реальних даних не перевірено
- 🟡 Перевірка на реальних CLI: Claude Code перевірено (haiku · medium); прапорець зусиль Codex, ланки Antigravity й Cursor у реальному запуску не перевірені
- ✅ Вичерпаний ліміт: розпізнавання помилки ліміту (`src/limits.ts`), пауза агента до скидання, передача задачі наступній ланці без втрати спроби, очікування, коли всі на паузі; картка агента «ліміт до HH:MM» + «Зняти паузу»; перевірено на mock-агенті
- ⬜ Розпізнавання ліміту на справжньому повідомленні CLI (формулювання взяті з відомих повідомлень, а не з реального вичерпання на цьому ПК)
- ⬜ Порівняльний прогін: одна задача паралельно на 2–3 ланках (лише кнопкою)
- ✅ Резервний API (платно): поки CLI встановлено й увійдено — тільки CLI; інакше Claude → Anthropic API (офіційний SDK), Codex → OpenAI API, Antigravity → Gemini API — лише з ключем у `.env` і перемикачем у Налаштуваннях (типово вимкнено); перевірено на фейковому API-сервері
- ⬜ Перевірка резервного API на реальних ключах (платні запити — лише з вашого дозволу)
- ✅ API-провайдери без CLI: DeepSeek, Kimi, MiniMax, Qwen, GLM, Grok, Mistral, OpenRouter (OpenAI-сумісний API, ключ у `.env`, перемикач платних запитів); адреси й моделі — з офіційної документації, перевірено на фейковому API-сервері
- ✅ Компактні картки агентів: можливості й примітки згорнуто; провайдери без ключа — спокійний статус «потрібен ключ API»
