# Roadmap

Пункти відповідають розділам ТЗ (`HidForge_Orchestrator_Development_Prompt.md`, §8–§11).

## Етап 0 — дослідження
- ✅ Клони трьох upstream із SHA, аудит коду, ліцензій, Windows-сумісності, безпеки → `UPSTREAM_AUDIT.md`
- ✅ ADR-001: вибір архітектури → `ADR-001-architecture.md`

## Етап 1 — ядро
- ✅ Структура репозиторію, dev-оточення, схема БД і міграції
- ✅ Модель задач, state machine, черга, журнал подій
- ✅ DAG scheduler: concurrency, priority, retry/backoff, timeouts/stall
- ✅ Блокування: один живий запуск на задачу, один writer на workspace (обмеження БД)
- ✅ Mock Agent, інтеграційні та concurrency-тести
- ✅ Git WorkspaceManager: worktree на задачу, clean-up після merge
- ✅ Відновлення після рестарту

## Етап 2 — реальні CLI
- ✅ Claude Code: реальний прогін задачі й планера
- 🟡 Codex CLI: з явною моделлю зі списку (`codex debug models`) реальні read-only сесії працюють (рецензент ✅); запис файлів блокує Windows-sandbox Codex на цьому комп'ютері (`Failed to write file`), обходити sandbox не можна
- ✅ Antigravity `agy`: реальний прогін задачі й планера без bypass
- 🟡 Cursor Agent CLI: встановлено й авторизовано, запуск без PowerShell, список моделей ✅; headless-прогін потребує довіри до каталогу — лише після вашого ввімкнення в Налаштуваннях (без нього не перевірено)
- ✅ Capability-based degradation: недоступний CLI не зупиняє проєкт
- ✅ Ліміти вартості: бюджет проєкту (зупиняє нові запуски) і ліміт задачі (`claude --max-budget-usd`); списки моделей з CLI (`agy models`, `cursor-agent models`, аліаси Claude) у підказках UI

## Етап 3 — робочий UI
- ✅ Dashboard: Projects / Tasks / Agents / Runs / Logs / Changes / Settings
- ✅ Залежності задач (таблиця з колонкою залежностей — допустимо за ТЗ)
- ✅ Живі логи, git diff, approve / reject
- ✅ Налаштування: тема, паралелізм, політика автовибору, бюджет, AI-рецензент, шаблони ролей (інструкції в контракті) і дозволи ролей (лише читання, дозволені агенти — примусово в планувальнику)
- ✅ Візуальний граф DAG / kanban: перемикач «Таблиця / Kanban / Граф» на сторінці задач (SVG-граф шарами за залежностями, без бібліотек)
- ✅ Єдина дизайн-система: токени, компоненти, AppShell, адаптивність (docs/DESIGN_SYSTEM.md)

## Етап 4 — інтелектуальна координація
- ✅ LLM-планер: ціль → валідований DAG → чернетки
- ✅ Автовибір агента за доступністю та політикою (cost-first / balanced / quality-first)
- ✅ Reviewer / repair loop: gate-и + repair-спроби; AI-рецензент QA + Security (advisory / required, repair із findings, API, UI), реальний прогін на Claude Code та agy
- 🟡 Інтеграційний агент: repair конфлікту в тій самій задачі ✅; окремий Integrator ⬜
- ✅ Облік витрат: usage кожного запуску, планера й рецензії; зведення по проєкту й агентах (USD від Claude Code, токени від усіх)
- ⬜ Зрозумілі звіти по проєкту
- 🟡 Пам'ять рішень: evidence, історія, відновлюваний план ✅; автоматичні ADR ⬜

## Обов'язкові тести (ТЗ §10)
- ✅ Перекриття двох workers у часі; залежна задача чекає
- ✅ Два workers не пишуть в один workspace
- ✅ Падіння / зависання / без результату
- ✅ Restart без втрат і дублікатів
- ✅ Блокування змін поза allowedPaths
- ✅ Failed tests → reject/retry, не merge
- ✅ Конфлікт merge не знищує роботу
- ✅ Відсутній CLI = not installed, UI працює
- ✅ Непідтверджена небезпечна команда не запускається
- ✅ Шляхи з пробілами й українськими літерами
